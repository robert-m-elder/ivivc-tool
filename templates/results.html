Applies the fitted in vitro-to-in vivo time relationship to the prediction dataset.

  • Calculation: each in vitro prediction time is entered into the fitted correlation model.
  • Output: predicted in vivo time.

Error propagation and uncertainty

{{ approach_descriptions['approach1']['prediction_error_html'] | safe }}

Approach 2: Prediction Results

Uses the separately fitted in vitro and in vivo curves in three different ways, depending on the prediction method.

  • Response-value ratio: uses both prediction time and response. The app compares the fitted in vivo and in vitro responses at the prediction time and uses that ratio to scale the observed prediction response. Output: predicted in vivo response.
  • Time-constant ratio: uses prediction time. When both fitted time constants are available, their ratio is used to scale the prediction time. Output: predicted in vivo time.
  • Observed-response inverse mapping: uses the observed prediction response. The app finds the time at which the fitted in vivo curve reaches that response. Output: predicted in vivo time.

These methods emphasize different features of the calibration profiles. Response-value ratio preserves time-dependent response differences, while time-constant ratio provides a simple overall time scaling; both are relatively straightforward to reproduce outside the app. Observed-response inverse mapping treats the supplied response as a degradation state and can capture nonlinear in vivo kinetics, but does not use the supplied prediction time or fitted in vitro calibration curve.

Error propagation and uncertainty

{{ approach_descriptions['approach2']['prediction_error_html'] | safe }}

Approach 3: Prediction Results

Uses interpolation-based mappings from the fitting datasets rather than a fitted parametric model.

  • Response-value scaling: uses both prediction time and response. The prediction time determines the in vivo/in vitro response ratio, which is then applied to the observed prediction response. Output: predicted in vivo response.
  • Time scaling: uses both prediction response and time. The observed response determines the in vivo/in vitro time ratio, which is then applied to the prediction time. Output: predicted in vivo time.

Approach 3 does not extrapolate lookup ratios: outside or undefined lookup values remain unavailable. A supported lookup can still produce a mapped time outside the observed in vivo range; that calculated result carries an extrapolation caution.

Model Selection & Summary

This tab lets you choose the fitted approach/model after reviewing model fits and comparison metrics. Prediction-specific methods are only shown when a prediction dataset was supplied and successfully processed.

  • User selection: the app does not rank or recommend a model in this tab. The first option is only the initial UI default.
  • Fit-only reports: if no prediction dataset was supplied, the selector lists only approach/model combinations and omits prediction-method choices.
  • Prediction reports: if prediction data were supplied, the selector also lists available prediction methods such as response-value-ratio rescaling, time-constant-ratio rescaling, or observed-response inverse mapping.
  • Report details: add the purpose, material or device, response and units, study identifiers, and your selection rationale. Blank fields are identified as not provided; the rationale is kept separately for each report selection.
  • Report summary: records source files and worksheets, observed and analyzed data coverage, preprocessing actually applied, settings, the selected method, results, and relevant limitations. Predictions include numerical values, available interval bounds, and mapping status.
  • Numerical appendix: includes source observations and the data actually used for fitting or direct mapping. Complete tables are exported regardless of browser pagination.
  • Word export: creates an editable .docx from the selected report content. Plotly figures are exported as static images and embedded in the Word file.
  • Manual review: plots, residuals, parameter uncertainty, cross-validation behavior, and scientific expectations can be considered together when documenting the rationale for the user-selected model.
